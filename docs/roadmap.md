# 律源 LexSource 项目画像与方向

## 项目概述

LexSource 是给律所内部使用的**自动情报系统**：由系统内的采集 Agent 按可配置日程，自动采集法律服务招投标与法律案件情报，筛掉无关信息后再入库。它服务律所合伙人、市场拓展和业务律师。

人打开系统，要的是已经采好、已经筛过的情报，而不是自己去检索、过滤、订阅一堆原始公告。它不是公开网站，也不是法律搜索引擎。

- 架构图

```text
  政采网 / 公共资源交易平台 / 最高法公开案例 / 律师上传
                         │
                         ▼
              采集 Agent（招标 | 案件）
         ReAct：思考 → 工具 → 观察
         发现 → 判定法律相关 → 抽取 → 验证
                         │
                         ▼
                  IntelStore (SQLite)
                         │
            ┌────────────┼────────────┐
            ▼            ▼            ▼
     登录后的值班台    所内 API     Markdown→Word/PDF
     状态灯 / 运行轨迹 / 已采集成品
```

定时调度（周期可配置）驱动采集 Agent。未登录不得进入情报台，也不得读写情报 API。

## 项目画像（目标状态）

律师登录后，工作台里已经摆着「现在还能投的法律服务标」和「所里能用的案件 brief」。这些条目是 Agent 按所内设定的周期采回来、判定与法律业务相关、验证过后留下的成品。人来是查看和导出，不是当筛选员。

一条标讯必须能回答：谁在买、买什么、预算多少、资格要求、何时截止、原文在哪、能不能投。一条案件必须能回答：这是哪类权威案例、争什么、判什么、律所能怎么用。

系统内部有明确分工的采集主体，而不是一个等人查询的检索框：

- **招标采集 Agent**：按日程从主通道发现公告，只留下法律服务相关标讯，过期或验证失败的不得显示为可投标。
- **案件采集 Agent**：按日程从可公开使用的权威案例源整编 brief，不把裁判文书网当默认可爬源。

采集周期由所内配置，而不是写死或默认关闭。Agent 的运行过程可查看：当前状态、下次何时跑、这一轮思考了什么、调用了哪些工具、观察结果是什么。律师日常不需要去点「开始采集」才能看到情报。

品质优先级：

1. **正确优于完整。** 截止日期和预算宁可标红待核，不可静默写错。
2. **Agent 筛过优于人来过滤。** 非法律采购、无关公告不得进入律师日常视图。少给一条不相关标，好过把一堆原始结果丢给人筛。
3. **可追溯优于黑盒自动化。** 每条情报保留原文和来源 URL，验证检查可展开。
4. **所内封闭优于公开便利。** 未登录看不到情报；这是律所内部系统，不是公众网站。
5. **时效优于覆盖长尾。** 先保证主通道按日程采到，再补省市源。

冲突时：漏掉一条偏远公告，好过把过期标显示成可投标；漏掉一条边界案例，好过把无关信息堆进工作台。

## 当前能力清单

- **所内登录**

  用户名口令登录，会话 Cookie。角色为管理员与律师。未登录只能看到登录页；情报 API 返回 401。失败登录不建会话。证据：`src/domain/auth.ts`、`src/store/db.ts`、`tests/auth.test.ts`。

- **招标采集 Agent**

  按日程跑 ccgp / ggzy；只把法律服务相关标讯入库，办公用品等无关公告在采集侧跳过。管理员可改间隔、启停、立即跑一轮。证据：`src/agents/`、`src/domain/relevance.ts`、`tests/agents.test.ts`、`tests/ingest.test.ts`。

- **案件采集 Agent**

  按日程跑最高法指导性案例源；裁判文书网仍硬失败且不落库。证据：`src/sources/spc.ts`、`src/agents/catalog.ts`、`tests/agents.test.ts`、`tests/run.test.ts`、`tests/verify.test.ts`。

- **招标情报入库与验证**

  抽取采购人、预算、截止日、资格；schema 与截止日回查；过期标不可投标。证据：`src/pipeline/extract.ts`、`src/pipeline/verify.ts`、`tests/extract.test.ts`、`tests/verify.test.ts`、`tests/ingest.test.ts`。

- **重大案件整编**

  抽取摘要、裁判要旨、法条、争议焦点，并生成律所 brief。证据：`src/sources/spc.ts`、`src/pipeline/extract.ts`、`tests/extract.test.ts`。

- **情报工作台**

  登录后是值班台：两个采集 Agent 的状态灯、ReAct 运行轨迹，以及当前可投标法律服务标与已整编案件 brief。管理员可立即采集并改日程；律师只看结果和轨迹。未接模型时灯为红，不得把失败伪装成空闲。证据：`src/web/dashboard.ts`、`src/agents/ops.ts`、`src/store/db.ts`、`tests/api.test.ts`、`tests/auth.test.ts`、`tests/ops.test.ts`。

- **三格式导出**

  Markdown 为唯一真源，再生成 Word / PDF。须登录。证据：`src/export/`、`tests/export.test.ts`、`tests/api.test.ts`。

- **辅助查找**

  `/api/intel` 仍可按类型、关键词过滤，但不是首页。证据：`src/store/db.ts`、`tests/api.test.ts`。

## 非目标（铁律）

- 不做面向公众的开放网站。未登录不得查看情报台，也不得通过 API 读取或写入情报。原因：这是律所内部系统。
- 不做订阅推送产品（邮件、企微、webhook 订阅匹配、outbox 投递）。原因：人要的是登录后直接看已采集结果，不是再维护一套订阅规则。
- 不把检索、过滤、关键词拼装当主交互。原因：过滤发生在采集 Agent 侧，律师不是筛选员。
- 不自动采集中国裁判文书网，也不把该网当作默认可爬源。原因：访问受限且合规风险高。律师上传或商业授权 API 另计，可走同一入库管道。
- 不把新闻全文转成自有版权库。社会重大影响案件只保留摘要、出处和交叉确认元数据。
- 不做投标文件编制、电子投标或采购代理。
- 不做面向公众的法律检索产品，不与法宝/威科抢全库。
- 不在未证实采集瓶颈前引入第二语言运行时（Go fetcher 除外号，且须有并发/延迟证据）。
- 不把 LLM 抽取结果在未过 schema 与 golden 回查时直接标为已验证。
- 不把采集 Agent 做成聊天机器人或「你问我搜」的对话检索。Agent 的职责是按日程采集并筛好，不是等人提问。

## 方向与意图

- **主通道时效**

  政采网与公共资源交易平台的法律服务标讯，按所内日程稳定入库。服务于时效，而不是靠人每天点采集。

- **重点省加深**

  在京沪粤浙苏交易中心补适配器，降低主通道漏标。服务于覆盖，但不牺牲验证，也不把人重新变成筛选员。

- **案件源扩展**

  公报案例、高院参考性案例、商业案例 API、律师上传 PDF 走同一入库管道，由案件采集 Agent 纳入日程。服务于案件情报，而不是另起一个案件库，也不是去爬裁判文书网。

- **可读中文 PDF**

  当前 PDF 为可下载归档（CJK 以转义写入标准字体）。方向是嵌入中文字体后与 Markdown/Word 同等可读。服务于导出完整性。

## 完成的样子

> 当律师登录后能直接看到 Agent 已按所内周期采好、筛过的法律服务标讯和案件 brief，而不需要自己拼筛选条件、配置订阅或先点一次采集时，这个项目才算立住。未登录的访问者看不到任何情报。

- 核心入库、验证、采集日程、登录鉴权、导出路径有自动化测试，回归能在 `bun test` 里被挡下；CI 必须挡住这些回归。
- 可投标列表里不应出现截止日已过、验证失败，或明显不属于法律服务的标讯。
- 每条入库情报都能回到原文 URL 或上传件。
- 采集失败可从运行记录看出，且失败条目不把脏数据标成可投标。
- 新增一级业务功能时，验收矩阵同步更新。

## 验收矩阵（业务能力覆盖矩阵）

> 覆盖底线（硬性规定）：
>
> 1. 每个一级功能至少有一条 Happy Path E2E。
> 2. 每个高风险功能至少覆盖一条失败路径。
> 3. 每个涉及权限的功能至少验证两种角色。
> 4. 每个会修改系统状态的操作至少验证一次失败后的恢复或回滚。
> 5. 每次新增一级业务功能，必须同步新增对应的 E2E 并更新本矩阵。

| 一级功能 | 风险级别 | Happy Path E2E | 失败路径 | 权限角色覆盖 | 失败恢复/回滚 | 证据（测试路径/用例） |
| --- | --- | --- | --- | --- | --- | --- |
| 所内登录 | 高 | ✅ 管理员/律师登录后可读情报 | ✅ 错密码 401 | 管理员、律师、未登录 | ✅ 失败登录不建会话 | `tests/auth.test.ts` |
| 招标采集 Agent | 高 | ✅ 日程默认开启；法律顾问入库 | ✅ 办公用品跳过不落库 | 管理员可跑/改日程，律师 403 | ✅ 无关公告不写库，非法间隔不改日程 | `tests/agents.test.ts`、`tests/ingest.test.ts`、`tests/auth.test.ts` |
| 案件采集 Agent | 高 | ✅ 录制 listing 入库指导性案例 | ✅ 裁判文书网源硬失败 | 管理员可跑，律师 403 | ✅ 禁源不落库 | `tests/agents.test.ts`、`tests/run.test.ts`、`tests/verify.test.ts` |
| 招标情报入库 | 高 | ✅ | ✅ | 管理员可手工入库，律师 403 | ✅ 硬失败不落库 | `tests/ingest.test.ts`、`tests/extract.test.ts`、`tests/api.test.ts`、`tests/auth.test.ts` |
| 重大案件整编 | 中 | ✅ | ✅ 未知源失败 | 须登录后可见 | ✅ 未知源不写库 | `tests/extract.test.ts`、`tests/ingest.test.ts`、`tests/api.test.ts` |

| 情报工作台 | 中 | ✅ 登录后默认可投标+案件，并可见 Agent 状态与 ReAct 轨迹 | ✅ 未接模型留下错误步骤且不落库 | 未登录登录页；律师可读轨迹不可开跑；管理员可开跑 | ✅ 模型未接 / 未知运行 404，不写脏数据 | `tests/api.test.ts`、`tests/auth.test.ts`、`tests/ops.test.ts`、`tests/agents.test.ts` |
| 三格式导出 | 中 | ✅ | ✅ 缺失条目 404 | 须登录 | 不适用（导出不改库） | `tests/export.test.ts`、`tests/api.test.ts` |

缺口与最低期望：

- 相关性关口当前是规则判定，不是对话式检索；若日常视图仍出现明显非法律采购，应加强采集侧判定，而不是把过滤交回给人。
- PDF 中文可读性仍是方向，不是当前已验收能力。
- 订阅推送已退出产品：`/api/subscriptions` 返回 410。证据：`tests/api.test.ts`。
