# 律源 LexSource 项目画像与方向

## 项目概述

LexSource 是给律所使用的案源情报库：把全国法律服务招投标公告，以及可公开使用的重大案件，收成律师能检索、验证、导出的资源。它服务律所合伙人、市场拓展和业务律师，而不是社会公众检索。

系统以一条 `IntelItem` 贯穿两类情报。公开网页或手工提交进入源适配器，经过抽取和验证后入库；律师在 Web 情报台过滤、打开原文链路，并导出 Markdown / Word / PDF。

- 架构图

```text
  政采网 / 公共资源交易平台 / 最高法公开案例 / 律师上传
                         │
                         ▼
              Source Adapter (ccgp | ggzy | spc-guiding)
                         │
                         ▼
           Extract → Verify → IntelStore (SQLite)
                         │
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
     Web 情报台      HTTP API      Markdown→Word/PDF
```

## 项目画像（目标状态）

律师打开情报台，应能在一个界面里看到“现在还能投的法律服务标”和“所里能用的重大案件 brief”。一条标讯必须能回答：谁在买、买什么、预算多少、资格要求、何时截止、原文在哪、能不能投。一条案件必须能回答：这是哪类权威案例、争什么、判什么、律所能怎么用。

品质优先级：

1. **正确优于完整。** 截止日期和预算宁可标红待核，不可静默写错。
2. **可追溯优于自动化。** 每条情报保留原文和来源 URL，验证检查可展开。
3. **时效优于覆盖长尾。** 先保证主通道快，再补省市源。
4. **律所可用优于百科全书。** 案件产出是 brief，不是裁判文书镜像。

冲突时：漏掉一条偏远公告，好过把过期标显示成可投标。

## 当前能力清单

- **招标情报入库**

  中国政府采购网、全国公共资源交易平台适配器可解析 HTML/文本；抽取采购人、预算、截止日、资格、服务类型。证据：`src/sources/ccgp.ts`、`src/sources/ggzy.ts`、`tests/extract.test.ts`、`tests/ingest.test.ts`。

- **重大案件整编**

  最高法指导性案例适配器抽取摘要、裁判要旨、法条、争议焦点，并生成律所 brief。证据：`src/sources/spc.ts`、`src/pipeline/extract.ts`、`tests/extract.test.ts`。

- **验证与可投标判定**

  schema、来源白名单、截止日、预算回查。裁判文书网来源硬失败且不落库。证据：`src/pipeline/verify.ts`、`tests/verify.test.ts`、`tests/ingest.test.ts`。

- **检索与过滤**

  按类型、地域、来源、关键词、可投标过滤。证据：`src/store/db.ts`、`tests/api.test.ts`。

- **三格式导出**

  Markdown 为唯一真源，再生成 Word / PDF。证据：`src/export/`、`tests/export.test.ts`、`tests/api.test.ts`。

- **Web 情报台**

  本地单页：列表、筛选、详情、导出链接。证据：`src/web/dashboard.ts`、`tests/api.test.ts`。

## 非目标（铁律）

- 不自动采集中国裁判文书网，也不把该网当作默认可爬源。原因：访问受限且合规风险高。律师上传或商业授权 API 另计。
- 不把新闻全文转成自有版权库。社会重大影响案件只保留摘要、出处和交叉确认元数据。
- 不做投标文件编制、电子投标或采购代理。
- 不做面向公众的法律检索产品，不与法宝/威科抢全库。
- 不在未证实采集瓶颈前引入第二语言运行时（Go fetcher 除外号，且须有并发/延迟证据）。
- 不把 LLM 抽取结果在未过 schema 与 golden 回查时直接标为已验证。

## 方向与意图

- **主通道时效**

  让政采网与公共资源交易平台的法律服务标讯，从发布到入库达到小时级。服务于“时效优于长尾”。

- **重点省加深**

  在京沪粤浙苏交易中心补适配器，降低主通道漏标。服务于覆盖，但不牺牲验证。

- **订阅推送**

  按地域 × 服务类型 × 预算规则推送到邮件或企微。服务于“律师不用天天刷库”。

- **案件源扩展**

  公报案例、高院参考性案例、商业案例 API、律师上传 PDF 走同一 `IntelItem` 管道。服务于重大案件资源，而不是另起一个案件库。

- **可读中文 PDF**

  当前 PDF 为可下载归档（CJK 以转义写入标准字体）。方向是嵌入中文字体后与 Markdown/Word 同等可读。服务于导出完整性。

- **所内权限**

  律所成员登录、操作留痕。服务于内部系统，而不是多租户 SaaS。

## 完成的样子

> 当律师能稳定地从公开主通道获得不过期的法律服务标讯，能打开可核对的重大案件 brief，并能把同一条情报导出为三种格式时，这个项目才算立住。

- 核心入库、验证、检索、导出路径有自动化测试，回归能在 `bun test` 里被挡下。
- 可投标列表里不应出现截止日已过或验证失败的标讯。
- 每条入库情报都能回到原文 URL 或上传件。
- 新增一级业务功能时，验收矩阵同步更新。

## 验收矩阵（业务能力覆盖矩阵）

> 覆盖底线（硬性规定）：
>
> 1. 每个一级功能至少有一条 Happy Path E2E。
> 2. 每个高风险功能至少覆盖一条失败路径。
> 3. 每个涉及权限的功能至少验证两种角色。
> 4. 每个会修改系统状态的操作至少验证一次失败后的恢复或回滚。
> 5. 每次新增一级业务功能，必须同步新增对应的 E2E 并更新本矩阵。

| 一级功能 | 风险级别 | Happy Path E2E | 失败路径 | 权限角色覆盖 | 失败恢复/回滚 | 证据（测试路径/用例） |
| --- | --- | --- | --- | --- | --- | --- |
| 招标情报入库 | 高 | ✅ | ✅ | 不适用（尚未做登录；引入权限后必须补两种角色） | ✅ 硬失败不落库 | `tests/ingest.test.ts`、`tests/extract.test.ts`、`tests/api.test.ts` |
| 重大案件整编 | 中 | ✅ | ✅ 未知源失败 | 不适用（同上） | ✅ 未知源不写库 | `tests/extract.test.ts`、`tests/ingest.test.ts`、`tests/api.test.ts` |
| 验证与可投标判定 | 高 | ✅ | ✅ 过期 / 裁判文书网源 | 不适用 | ✅ 失败条目不可投标且禁源不落库 | `tests/verify.test.ts`、`tests/ingest.test.ts` |
| 检索与过滤 | 低 | ✅ | 不适用（只读查询） | 不适用 | 不适用（不修改状态） | `tests/api.test.ts` |
| 三格式导出 | 中 | ✅ | ✅ 缺失条目 404 | 不适用 | 不适用（导出不改库） | `tests/export.test.ts`、`tests/api.test.ts` |
| Web 情报台 | 低 | ✅ 页面与 API 契约 | 不适用（只读壳） | 不适用 | 不适用 | `tests/api.test.ts` dashboard html is served |

缺口与最低期望：权限系统尚未存在，矩阵标“不适用”；一旦加入登录，必须补“有权/无权”两条 E2E。PDF 中文可读性仍是方向，不是当前已验收能力。
